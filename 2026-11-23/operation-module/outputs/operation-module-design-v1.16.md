## 4. 筛选形态

### 4.1 统一规则（不新造控件）

| 控件 | 规则 |
|---|---|
| text 单模式 | 模糊匹配（`like`），空值不产生条件；不可切换模式 |
| text 多模式 | 六模式：等于 / 不等于 / 模糊 / 左匹配 / 右匹配 / 批量；**默认模糊**；批量上限 500，超限提示不静默截断（复用 `utils/textFilter.ts` 的 `TextMatchMode`，与后端 `TextFilterMode` 同口径） |
| select 单选 | 下拉单选，默认空（全部）；用于网点类 |
| select 多选 | 下拉多选，默认空（全部）；枚举类默认不过滤 |
| daterange | 固定日期区间，默认近 30 天？→ **默认空（全部）**，快捷项：今天/近 7 天/近 30 天/本月；列设置只读显示"固定按日期区间查询" |
| numberrange | 最小/最大两格，默认空；金额按元、重量 3 位小数 |

## 5. 默认排序与分页

| 项 | 结论 |
|---|---|
| 默认排序 | `create_time DESC`，第二排序键 `waybill_no DESC`（稳定分页，避免同一秒多条时翻页重复/漏行） |
| 可排序字段 | 除序号、操作外全部；服务端排序；枚举按码值、金额/数量按数值、日期按时间 |
| 默认每页 | **20**（D7）；可选 20 / 50 / 100 |
| 分页位置 | 工具条右侧（v1.14 定稿） |
| 合计口径 | 当前筛选条件下**全部数据**，后端与列表同一查询返回 |
| 稳定性 | 排序键不足时始终追加 `id DESC` 兜底，禁止不确定顺序 |

## 6. 操作列与行操作

列宽 180（新增「改单」后由 160 放宽），`fixed=right`，居中；按钮顺序：`详情`、`改单`、`子单(n)`（仅有子单）、`作废`。打印不做（D10）。

| 按钮 | 显示条件 | 权限 | 说明 |
|---|---|---|---|
| 详情 | 始终 | `operation:waybill:query` + 数据权限可读 | 跳转详情页 `/operation/waybill/:id`（见第 7 节） |
| 改单 | 状态 ∈ 20–90（`20 ≤ status < 100`）且非子单终态；100/110/120/130/900 置灰并提示原因 | `operation:waybill:amend` + 写权限 + 网点管理员及以上（一期直接生效；二期审核另加审核权限） | 跳转改单页（开单页可编辑副本，见第 8 节），不弹窗；原因必填 |
| 子单(n) | `is_child=0` 且存在有效子单 | 同上 | 打开子单清单弹窗；n 为有效子单数；运单号点击同入口 |
| 编辑 | **v1.16 起以「改单」替代**，不再单列「编辑」 | — | 改单字段边界见 8.2 |
| 作废 | `status=20` | `operation:waybill:void` + 写权限 + 管理员及以上（D5） | 二次确认 + 必填原因；写 `biz_waybill_log(action_type=4)` 与前后快照 |
| 打印 | 本期不显示（D10） | — | 二期随打印模板 |
| 删除 | 不提供 | — | 业务单据只作废不物理删除 |

- 无权限按钮**置灰并给 tooltip 原因**，不隐藏（v1.14 3.2.4）。
- 越权访问详情：后端返回 `403 无权访问该运单`，不泄露记录是否存在。

## 8. 运单改单

### 8.1 入口与承载

- 入口：列表操作列「改单」、详情页底部「改单」；跳转 `/operation/waybill/:id/amend`。
- 页面 = 开单页**可编辑副本**：与详情页共用 `fieldGroups` 分区与顺序；可改字段放开编辑，不可改字段保持灰底只读并加锁标识 + tooltip 原因。
- 顶部标识条与详情页一致，额外显示「改单」标识；底部：`取消`、`保存改单`（保存时弹原因输入，必填 ≤200 字）。
- 保存成功回到详情页并刷新「改单信息」tab。

### 8.2 字段边界

**允许修改**

| 分区 | 字段 | 校验 |
|---|---|---|
| 发货方 | 发货单位、发货人、发货电话、发货地址 | 发货人/电话/地址必填，手机号格式沿用开单 |
| 收货方 | 收货单位、收货人、收货电话、收货省/市/区县、收货详细地址 | 收货人/电话/地址必填；省市区县必须选到区县级 |
| 货物明细 | 名称、类型、包装、件数、重量、体积、备注 | 至少 1 行；主表件数/重量/体积汇总随明细重算 |
| 费用 | 运费、送货费、提货费、其他费、回单费、制单费、保费、现返、欠返、代收货款 | 金额 BigDecimal 两位；非负；送货方式为送货/大车直送时送货费必填 |
| 支付与配送 | 支付方式、送货方式 | 见 8.4 金额一致性 |
| 其他 | 备注 | ≤500 字 |

**不允许修改（锁定并说明原因）**

| 字段 | 锁定原因 |
|---|---|
| 运单号 | 业务主键 |
| 目的地与线路（含 `route_keys`、路由节点、运达网点、时效/里程快照） | 改线路会让已配载/已发运的链路失效，需单独「改路由」流程，本期不做（明确写入方案，避免以后当成遗漏） |
| 开单网点、开单时间、开单员 | 审计口径 |
| 子母单关系、母单号 | 已拆分单据的归属不可变更 |
| 来源预开单号 | 与预开单关联关系 |

- 补充：货物件数/重量/体积可改，但**不改路由节点的时效/里程快照**；列表与详情的线路信息仍显示开单时快照。

### 8.3 可改状态

| 状态 | 可改 | 说明 |
|---|---|---|
| 20 已揽收 ~ 90 末端到车 | 是 | `20 ≤ status ≤ 90`，含 30 网点装车、40 网点发车、50 分拨到车、60 分拨卸车、70 分拨装车、80 分拨发车 |
| 100 到站待提 / 110 到站待送 / 120 到站待转 | 否 | 已进入末端交付，按钮置灰 |
| 130 已签收 | 否 | 已完结 |
| 900 已作废 | 否 | 已作废 |

- 置灰 tooltip：`该状态不可改单：{状态名}`；后端同样返回 `400 当前状态不可改单`，前端不可绕过。
- 改单不改变运单状态，也不推进状态。

### 8.4 金额一致性与校验（与开单共用，不复制规则）

- 复用 `WaybillAmountCalculator` 与 `WaybillService` 的校验：
  - 运费合计 = 运费 + 送货费 + 提货费 + 其他费 + 回单费 + 制单费 + 保费；
  - 返款合计 = 现返 + 欠返；
  - 有效运费 = 运费合计 − 返款合计。
- 支付方式：
  - **单一支付方式**：对应支付运费自动等于运费合计，前端不可编辑，后端强制重算；
  - **多笔付**：现付 + 到付 + 月结 + 回付 之和必须等于运费合计，否则 `400 支付分配金额合计必须等于运费合计`。
- 改单保存必须重走上述校验（**D13 已定：必须**）；任一规则不满足即拒绝保存，返回明确提示，不做"部分保存"。
- 送货方式与送货费必填沿用开单口径；代收货款 > 0 时收款四要素必填。
- 前端只做即时提示，**服务端校验才可信**。

### 8.5 留痕（复用 `biz_waybill_log`，不新建表）

- 每次改单写一条 `action_type=6`：`reason` 存改单原因（必填），操作人与时间取登录上下文，`before_snapshot/after_snapshot` 沿用现有快照契约。
- 字段级 diff 作为 action 6 的扩展键写入 `after_snapshot.changes`（基础快照键不变，其它动作不写该键）：

```json
{"changes":[
  {"field":"senderPhone","label":"发货电话","before":"13800000001","after":"13900000002"},
  {"field":"goods[0].weight","label":"货物明细第1行·重量(kg)","before":"240.500","after":"260.000"},
  {"field":"deliveryFee","label":"送货费","before":"120.00","after":"150.00"}
]}
```

- **二期预留审计字段（D12 已定）**：`biz_waybill_log` 增加三列，一期只写默认值、不参与任何逻辑：

| 列 | 类型 | 一期写入值 | 二期用途 |
|---|---|---|---|
| `audit_status` | `TINYINT UNSIGNED NOT NULL DEFAULT 0` | `0`（无需审核/直接生效） | 10 待审核、20 审核通过、30 审核驳回 |
| `auditor_id` | `BIGINT UNSIGNED NULL` | `NULL` | 审核人 `sys_user.id` |
| `audit_time` | `DATETIME NULL` | `NULL` | 审核时间 |

- 改单记录现状（一期）：「改单信息」tab 读 `changes` 渲染改单时间、操作人、原因、字段/原值/新值；无记录空态「暂无改单记录」。审计三列不展示。
- 表结构变更**只出稿未执行**：`outputs/ddl/V23__waybill_log_amend_audit_pending.sql`（含回滚）；`action_type` 注释补 `6=改单` 也在该稿内。家伟批准后移入 Flyway 执行。

### 8.6 权限与生效方式

- 权限点 `operation:waybill:amend`，与作废对齐（网点管理员及以上）；子单改单同时校验母单数据权限。
- **一期（D12 已定）**：改单保存**直接生效**并写记录；没有待审态、没有审核接口、不新增运单状态。
- 二期若接入审核：复用 `audit_status / auditor_id / audit_time`，只加流程与页面，不改表结构；审批是否阻塞生效由二期再定。

### 8.7 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| PUT | `/api/v1/operation/waybills/{id}/amend` | 请求：`reason`、`version`（乐观锁）、可改字段集合、`goodsList`；服务端校验状态/权限/字段白名单，重算金额，忽略不可改字段；写日志时 `audit_status=0`、`auditor_id/audit_time=NULL`；返回更新后运单 + `changes` |
| GET | `/api/v1/operation/waybills/{id}/amend-logs` | 改单记录；**建议并入详情返回 `amendLogs`**，减少一次请求 |

- 错误码：400 状态不可改 / 金额不平 / 必填缺失 / 字段越界；403 无权限；409 版本冲突（并发改单）。

### 8.8 与开单页/详情页的复用

- 同一份 `fieldGroups` 配置驱动三种形态：**开单（可编辑 + 校验）→ 详情（全只读）→ 改单（白名单可编辑，其余只读）**。
- 金额计算与校验只保留后端一处；前端提示不作为可信校验。
- 理由：避免规则复制造成"开单能存、改单存不进"或反向不一致。

### 8.9 子单改单

- 子单同样走改单流程；母单改单不联动子单（件数/重量各自独立）；拆分/合并联动属后续阶段，不在本期。

### 8.10 二期预留：改单审核与企业微信对接（本期不建表、不做页面）

- 本期只写设计备忘，**不进 DDL、不做配置页、不做回调**；二期实施时按下列清单落地。
- 需要新增的配置项（建议单独配置表或系统参数分组 `wecom.amend.audit`）：
  - 企业微信应用：`corp_id`、`agent_id`、`secret`（加密存储，页面不回显明文）；
  - 审批模板：`approval_template_id`、模板字段映射（运单号 / 改单原因 / 金额变化 / 操作人 / 详情链接）；
  - 回调：`callback_url`、`callback_token`、`callback_aes_key`；
  - 消息接收人映射：按网点/角色配置审核人 `userid` 列表，及审批结果通知对象；
  - 开关：`audit_enabled`（默认 false）、超时策略（超时自动通过/驳回）。
- 与一期的衔接：`biz_waybill_log.audit_status` 一期恒为 0；二期开启审核后，新改单记录写 10 并等待回调更新为 20/30，历史记录保持 0 视为"无需审核"。
- 二期需要新增的接口（仅备忘）：发起审核、审批回调、审核结果查询；不改动现有改单保存接口的字段语义。

- 拦截器需覆盖 `biz_waybill`、`biz_waybill_route_node`、`biz_waybill_goods`、`biz_waybill_log`；`biz_waybill_no_seq` 已豁免登记。
