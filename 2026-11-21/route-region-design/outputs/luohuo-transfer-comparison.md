> 目的：外转/直送路由回退到 luohuo 口径，避免自创字段/交互/命名。

## 一、luohuo 实现口径（逐项）

### 1.1 表字段与含义（`sys_route`）

| 字段 | 类型 | 含义 / 口径 |
|---|---|---|
| `id` | BIGINT PK | 主键 |
| `route_code` | VARCHAR(32) | 后端生成：`区划编码_ZT`（直送）/`区划编码_WZ`（外转）；切类型时同步改后缀 |
| `route_name` | VARCHAR(128) | 默认 = 区划全路径；可改；批量加入会覆盖为区划全路径 |
| `route_type` | TINYINT | 1=直送，2=外转；默认 2 |
| `region_code` | VARCHAR(12) | 目的地行政区划编码 |
| `region_level` | TINYINT | 目的地粒度：2=市，3=区县，4=乡级 |
| `region_full_name` | VARCHAR(200) | 目的地全路径（冗余，展示/搜索） |
| `carrier_id` | BIGINT NULL | 默认承运商；NULL=未配置；仅外转可挂 |
| `status` | TINYINT | 1=启用，0=停用 |
| `sort_order` | INT | 排序，默认 0 |
| `remark` | VARCHAR(500) | 备注 |
| `org_id` | BIGINT | **实际业务值 = 适用网点**（页面“配置网点”）；DDL/模型注释写的是“归属机构（总部）”，与实现不一致 |
| `is_deleted` | TINYINT | 逻辑删除 |
| `create_by/create_time/update_by/update_time` | — | 审计 |

索引：`idx_region`、`idx_type`、`idx_carrier`、`idx_status`；**无唯一索引**。DDL 注释“目的地唯一，应用层 upsert”已过时——实际唯一口径是“适用网点 + 目的地”。

### 1.2 编码生成规则

- 直送：`{region_code}_ZT`；外转：`{region_code}_WZ`。
- 单条编辑不允许改目的地/类型；类型通过“切直送/切外转”批量接口切换，编码后缀同步重写。
- 无冲突后缀逻辑（不同网点同一区划会产生相同 route_code，依赖无唯一索引才可共存）。

### 1.3 页面结构（截图 + 源码）

- 顶部“配置网点”单选（网点头像=机构类型 3，启用），页面所有数据按该网点过滤。
- 左栏“区划库”：关键词搜索（回车/按钮）+ 级别筛选；表头内嵌筛选：级别/省/市/区县/乡级/配置；配置列显示“已配置”；支持勾选未配置区划。
- 中间“加入 / 移除”两个竖向按钮。
- 右栏“已配置路由（网点名）”：
  - 分页 20/50/100（截图为 10/页，用户配置）。
  - 工具条：切直送、切外转、挂承运商、启用、停用；右侧重置、导出、列设置。
  - 行内操作：编辑、删除。

### 1.6 与承运商/区划/适用网点关系

- 承运商：仅外转可挂；可为空；列表显示“未配置”（红色）；被路由引用时删除拦截（`count_route_references`）。
- 区划：目的地只能选市/区县/乡级；区划库搜索要求关键词或级别，单次最多 50 条；可过滤“未配置”。
- 适用网点：路由按网点配置，唯一键“网点 + 目的地”；页面必须先选网点；列表/下拉按网点过滤。
- 写权限：仅总部机构用户（org.parent_id=0）或超管；列表/详情不接数据权限。

## 二、yunshu 现状（已实现，未最终确认）

### 2.1 数据模型

- `sys_route_transfer`：`route_code`、`route_name`、`transfer_type`（1=直达 2=外转）、`apply_dept_id`（适用网点，业务）、`region_code/level/full_name`、`carrier_id`、`owner_company_id`、`status`、`sort_order`、`remark`、`dept_id`（权限审计锚点）、审计字段、`deleted`；`uk_route_code` 全局唯一。
- 授权：`sys_route_company`（route_scope=2），支持 0 号行“全部分公司（动态）”。

### 2.2 页面与交互

- Tab2“直达/外转”：标准单列表 + 新增/编辑抽屉。
- 工具条：新增路由、批量授权（总部）；重置/导出/列设置/分页。
- 列：序号、路由编码、路由名称、类型、适用网点、目的地、承运商、创建公司、授权范围、状态、排序号、更新时间、操作。
- 筛选：编码、名称、类型、适用网点（树选择）、目的地（编码/名称）、状态、授权范围；排序服务端白名单。
- 行操作：编辑（创建公司/总部）、授权（总部）、删除（无其他授权时）；删除拦截文案“路由被其他公司使用，不能取消，取消授权即可”。
- 抽屉：类型（直达/外转）、适用网点、目的地（省/市/区县三级）、名称（默认全路径）、承运商（仅外转）、状态、排序、备注；类型/适用网点/目的地必填；切直达自动清空承运商；编码自动生成。
- 授权弹窗：授权列表（分公司/来源/授权人/时间）、手动授权、取消授权、0 号行提示“已授权全部分公司（动态，含后续新增）”；批量授权。

## 四、仅保留的必要差异（逐条原因）

1. **dept_id（审计锚点）**：luohuo 用 org_id 直接承载适用网点；yunshu 多公司下 dept_id 仅审计留痕，业务适用网点另用 apply_dept_id，避免权限锚点与业务字段混用。
2. **owner_company_id（创建公司）**：luohuo 路由仅总部维护；yunshu 允许分公司创建，需要归属判定编辑/删除权限。
3. **sys_route_company（路由授权分公司）**：luohuo 路由为全网字典；yunshu 需要跨公司共享与回收，授权关系是既有业务硬要求。
4. **末端网点适用公司导致的可见范围过滤**：luohuo 无适用公司概念；yunshu 的 `/depts/manage-scope` 与承运商/路由可见性依赖该关系。
5. **开单侧直达优先排序**：luohuo 落货路由下拉无排序策略；yunshu 开单要求 直达 > 网络完整链路 > 外转、首条推荐，属既有开单规则。
6. **全局 route_code 唯一 + 冲突后缀**：luohuo 无唯一索引，同一区划可在多网点重复编码；yunshu 需要全局唯一与可追溯，保留后缀 `_2`。若确认改为“按网点唯一”，则可完全对齐 luohuo 编码且去掉后缀。

## 五、luohuo 自身缺陷/风险（单独列出，不建议照搬）

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | `org_id` 注释为“归属机构（总部）”，实际存适用网点 | 误导后续开发与数据统计 | 若照搬表结构，注释必须改为“适用网点” |
| 2 | DDL 注释“目的地唯一”，实际按“网点+目的地”，且无唯一索引 | 并发批量加入可产生重复行；同区划多网点编码重复 | 增加唯一索引 `(org_id, region_code)`（或 yunshu 的 `(apply_dept_id, region_code, transfer_type)`） |
| 3 | 批量加入强制 `route_type=2`，并覆盖名称/级别/全称、恢复已删除 | 自定义名称被批量操作覆盖；已删除路由“复活” | 仅新建/恢复时写默认名称；已有记录不覆盖名称；恢复需二次确认 |
| 4 | 切类型无条件重写 route_code | 外部引用/打印缓存可能失配 | 切类型前校验是否被单据引用；或编码与类型解耦 |
| 5 | 删除为纯逻辑删除，无引用校验 | 单据引用已删除路由 | 增加引用校验或删除前提示 |
| 6 | 外转未配置承运商显示红色“未配置” | 违反家伟“禁止亮红亮绿” | yunshu 用中性灰“未配置” |
| 7 | `GET /options` 无功能权限、org_id 由客户端传入 | 登录用户可枚举任意网点路由 | 服务端校验网点可见性 |
| 8 | 列表读接口不接数据权限且无网点隔离（仅按传入 org_id） | 跨网点数据可被读取 | yunshu 用管理范围 + 授权关系显式过滤 |
| 9 | 批量更新无并发控制/版本号 | 并发覆盖 | 需要时加乐观锁 |
