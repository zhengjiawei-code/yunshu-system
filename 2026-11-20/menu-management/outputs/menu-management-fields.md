# 菜单管理 · 字段清单（v1.1，端归属已移除）

> 依据：`2026-11-20/project-scaffold/outputs/scaffold-plan.md` 第 9、10 节；`luohuo-frontend-spec.md` 2.4.1 / 3.1。
> 本轮只出清单，**不写页面代码**；确认后才进入实现。
> 约定：字段名与接口契约为 camelCase（后端 Jackson 统一转换），数据库列为 snake_case。

## 0. 交互总览

- 单页树表，不是左树右表。
- 三个入口：**新增目录**（主按钮）、**新增菜单**（次按钮）、行内**新增子目录 / 新增子菜单 / 新增按钮**。
- 抽屉统一 640px，底部按钮右对齐（取消 / 确定）。
- 类型由入口决定，表单内只读展示，**不允许用户自己切类型**，避免误建。
- 编辑态复用同一抽屉，标题改为“编辑目录 / 编辑菜单 / 编辑按钮”，类型仍只读。

## 4. 三类表单差异速查

| 字段 | 目录 | 菜单 | 按钮 |
|---|---|---|---|
| parentId | 可空（顶级）/目录 | **必填**/只能目录 | 固定菜单、不可改 |
| routePath | 必填，单段 `/system` | 必填，绝对路径 `/system/user`，需父路径前缀 | 无 |
| component | 无 | 必填 | 无 |
| perms | 无 | 选填 | **必填** |
| icon | 必填 | 必填 | 无 |
| redirect | 选填（留空自动） | 无 | 无 |
| terminalType | 无（继承 PC） | 必填（本期固定 PC） | 无 |
| keepAlive / affix | 无 | 有 | 无 |
| visible | 有 | 有 | 无 |
| status / sortOrder / remark | 有 | 有 | 有 |

规则差异重点：**目录必须有路由无组件；菜单必须有组件；按钮必须有权限标识**（方案 9.1 硬边界）。

## 5. 树表列清单

| # | 列 | 最小宽 | 对齐 | 显示规则 |
|---|---|---|---|---|
| 1 | 菜单名称 | 240 | 左 | 树列，前置图标；目录加粗；按钮缩进显示 |
| 2 | 类型 | 90 | 居中 | 目录=info / 菜单=primary / 按钮=warning（StatusTag） |
| 3 | 路由地址 | 200 | 左 | 按钮显示 `—`；超长省略 + title |
| 4 | 组件路径 | 180 | 左 | 目录/按钮显示 `—` |
| 5 | 权限标识 | 160 | 左 | 无则 `—`；等宽字体 |
| 6 | 终端 | 90 | 居中 | PC / APP / PC+APP；按钮显示继承值 |
| 7 | 排序 | 80 | 右 | 数字，tabular-nums |
| 8 | 显示 | 80 | 居中 | 显示/隐藏；按钮显示 `—` |
| 9 | 状态 | 80 | 居中 | 启用/禁用 |
| 10 | 最后修改时间 | 170 | 中 | `YYYY-MM-DD HH:mm:ss`（后端 `updateTime` 原样展示，含秒；2026-11-20 家伟裁决保持现状） |
| 11 | 操作 | 240 | 右 | 固定右侧，不随横向滚动（4 个动作实测需约 200px，故 220→240） |

- 以上为**最小宽**；实际实现由 SmartTable 按 `max(表头宽, 当前页最宽内容 + 内边距)` 自适应，可高于最小宽（上限 240，超出截断 + 表格级 tooltip）。
- 11 列总宽大于多数窗口，表格必须提供清晰可辨的横向滚动条（高度 10px）；内容不因列宽固定而被无故截断。

- 排序：**不提供点击列头排序**，树内顺序固定为 `sortOrder asc, id asc`，与侧栏一致。
- 总最小宽约 1610px，窄屏横向滚动；操作列固定。
- 行高按规范（紧凑 40 / 默认 44），树表用默认 44。

**操作列动作**

| 节点 | 动作（从左到右） |
|---|---|
| 目录 | 新增子目录 / 新增子菜单 / 编辑 / 删除 |
| 菜单 | 新增按钮 / 编辑 / 删除 |
| 按钮 | 编辑 / 删除 |

- 删除为危险色；有子节点直接拒绝并提示“请先删除子节点”。
- 被角色/用户引用时二次确认，提示引用数量，确认后级联删除关系记录。

**筛选与工具条（豁免范围）**

- 左侧：新增目录（主）/ 新增菜单 / 展开全部 / 收起全部。
- 筛选：菜单名称（模糊）、类型（目录/菜单/按钮）、状态。
- 右侧：重置 → 刷新。
- **不做分页、不做合计行、不做导出、不做列设置**（规范 3.1 树形配置表例外，D4）。
- 筛选命中子节点时保留其祖先链，避免树断裂。
- 空态：无数据时显示“暂无菜单数据”+ 新增目录入口；筛选无结果显示“没有匹配的菜单”。

## 6. mock 与接口契约对应关系

前端统一封装在 `src/api/system/menu.ts`，骨架阶段由 `VITE_USE_MOCK` 切换数据源，**页面代码不变**。

| 前端方法 | 后端接口 | 入参 | 返回 | mock 行为 |
|---|---|---|---|---|
| `getMenuTree()` | `GET /api/v1/system/menus/tree` | 无（管理页全量） | `MenuNode[]`（嵌套，含禁用/隐藏/按钮） | 返回 `mock/menuManage.ts` 的完整树（14 目录 + 40 菜单，含按钮示例） |
| `getMenuDetail(id)` | `GET /api/v1/system/menus/{id}` | id | `MenuNode` | 从 mock 树中查找 |
| `createMenu(data)` | `POST /api/v1/system/menus` | `MenuSavePayload` | `{ id }` | 内存追加并返回自增 id |
| `updateMenu(id, data)` | `PUT /api/v1/system/menus/{id}` | id + `MenuSavePayload` | `void` | 内存替换 |
| `deleteMenu(id)` | `DELETE /api/v1/system/menus/{id}` | id | `void` | 内存删除，保留子节点校验 |
| `sortMenus(ids)` | `PUT /api/v1/system/menus/sort` | `number[]` | `void` | 二期启用，一期不调用 |
| `getViewComponents()` | 无（前端本地） | 无 | `string[]` | 取 `import.meta.glob('@/views/**/*.vue')` 的 key，去掉前缀与 `.vue` |

**`MenuSavePayload`（三类共用，按类型裁剪）**

```ts
interface MenuSavePayload {
  parentId: number
  menuType: 1 | 2 | 3
  menuName: string
  routePath?: string    // 目录/菜单
  component?: string    // 菜单
  perms?: string        // 菜单选填、按钮必填
  icon?: string         // 目录/菜单
  redirect?: string     // 目录
  terminalType?: 'PC' | 'APP' | 'PC,APP'  // 菜单
  keepAlive?: boolean
  affix?: boolean
  sortOrder: number
  visible: boolean
  status: boolean
  remark?: string
}
```

**与现有 mock 的衔接**

- 端归属移除后，`src/mock/menus.ts` 的 `internalMenus` 即全量 40 个菜单（预开单已并入运营管理），不再有 `clientMenus`。
- 管理页树 = `internalMenus` + 按钮示例，由 `src/mock/menuManage.ts` 生成，避免复制。
- 后端就绪后仅把 `getMenuTree` 等方法的 mock 分支删掉，页面与字段不动。

**接口约定**

- 统一外层 `{ code, message, data }`，`code=200` 为成功；`request.ts` 已解包 `data`。
- 树接口一次返回完整树，不分页；排序由后端按 `sortOrder, id` 完成。
- 保存接口由后端做同名/同路径唯一性最终校验，前端只做即时提示，错误信息走后端 `message`。

## 7. 已确认口径（2026-11-20 家伟裁决）

| 编号 | 问题 | 结论 |
|---|---|---|
| ① | 按钮是否显示在树表 | **显示**为菜单子行，默认折叠、不撑开树；展开菜单后可见 |
| ② | 目录有子节点后改路由 | **禁止修改**（含其他会影响子路径的字段） |
| ③ | 目录改端归属是否级联子孙 | **已作废**（2026-11-20 端归属整体移除，规则与弹窗一并删除） |
| ④ | `perms` 唯一性 | 按钮**全局唯一**；菜单不强制 |
| ⑤ | `component` 文件不存在能否保存 | **允许保存**，仅给警告 |
| ⑥ | 深度上限是否含按钮 | 4 级，**只算目录+菜单**，按钮层不计 |
| ⑦ | 编辑时能否换父级 | 目录与菜单**允许**（带环检测）；按钮不允许 |
| ⑧ | 目录是否维护端归属 | **已作废**（2026-11-20 端归属整体移除，表单字段删除） |
| ⑨ | 菜单上级范围 | **只能选目录**；方案 9.4 原“可挂目录/菜单”作废 |

> 方案文档已同步：`scaffold-plan.md` 9.4 表格改为“只能目录”，10.3 注明按钮子行默认折叠，10.5 校验规则补齐以上 9 条。
