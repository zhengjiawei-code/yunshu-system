## 0. 使用约定

### 0.1 规则等级

| 等级 | 含义 | 处理方式 |
|---|---|---|
| **硬性** | 家伟明确要求或已写入项目硬约束 | 必须遵守，违反即为交付不合格 |

| **已定稿** | 原待确认项，家伟已裁决 | 按第 6 节决策记录执行 |

### 0.2 优先级与冲突处理（硬性）

1. 任何代码 / 样式 / 配置改动必须经家伟明确同意后才可执行，未经同意禁止擅自修改。
   `来源：2026-10-28 会话 6ae14f4f（用户明确要求）`
2. 家伟要求与既有规范冲突时，禁止自行取舍，必须先指出冲突点、给出选项，由家伟裁决。

   `来源：2026-11-07 会话 d70cb29e（承运商对账发起页多出未要求内容，定为硬规则）`
4. 任务完成后必须反查验证（构建、接口实测、浏览器实测），禁止以"代码已改"代替验证。
   `来源：project_memory 一、协作流程`

# 一、前端风格

## 1.1 视觉调性（基线）

- 设计语言名称：**「墨蓝 · 素笺」**——低饱和、纸面感、精密线条。
- 风格底线：不使用 Element Plus 默认高饱和色；不做彩色图标；不叠加多层重阴影；渐变只用于品牌面板这类大面积底，不用于按钮/标签等组件。
- 大面积底色以三种为主：页面底 `#f4f6f9`、卡片白 `#ffffff`、侧栏墨色 `#1a2432`。
- 业务内容区追求最大屏占比：顶栏 56px、标签栏 32px、页内边距 16px，1725×1191 视口下核心内容区屏占比实测 93.3%。
  `来源：2026-10-28 会话 6ae14f4f（全局设计令牌统一）；源码：frontend/src/styles/variables.css`

## 1.3 语义色使用规则（硬性）

### 1.3.1 状态标签

存在两套组件，用途不同，禁止页面自己写 `el-tag` 或纯文字状态：

| 组件 | 形态 | 规格 | 用途 |
|---|---|---|---|
| `StatusTag.vue` | 胶囊 + 左侧 6px 圆点，1px 透明边框 | `padding:1px 9px`、`border-radius:999px`、字号 12px、字重 500、圆点 6px | 通用业务状态 |
| `ReconStatusTag.vue` | 胶囊、纯文字、无圆点；"进行中且带悬浮信息卡"时追加一个 12×12px 圆形 `i` 信息点（字号 9px） | 高 **22px**、左右 padding **9px**、圆角 **11px**、字号 **12px**、行高 1、1px 边框 | 核销 / 对账 / 审核 / 结算 |

- ReconStatusTag 三态映射（硬性，三模块必须一致）：
  - 核销：1 无需核销 / 2 未核销 → info；3 核销中 / 4 部分核销 → warning；5 已核销 → success
  - 对账：1 未对账 → info；2 对账中 → warning；3 已对账 → success
  - 审核：0 待审核 → warning；1 已审核 → success；2 已驳回 → danger
  - 结算：0 未结算 → info；1 已结算 → success
- ReconStatusTag 色板（源码现值，定稿；不再走主题令牌）：

| 语义 | 文字色 | 底色 | 边框色 |
|---|---|---|---|
| info | `#909399` | `#f4f4f5` | `#dcdfe6` |
| warning | `#d9822b` | `#fff7e8` | `#f5c26b` |
| success | `#529b2e` | `#f0f9eb` | `#b3e19d` |
| danger | `#c45656` | `#fef0f0` | `#fab6b6` |
| 悬浮信息点 `i` | `#ffffff`（字号 9px） | `#eda13c` | — |

> 历史值：曾讨论过统一到低饱和主题色 `#61728b / #b8863a / #4e7a60 / #a95454`，已废弃；状态标签按上表执行。
- 状态色由组件统一提供，页面禁止再定义状态色常量；同状态在三个模块的样式参数（高度、圆角、字号、padding、色值）必须逐项一致。
- 业务标记类内容（如"已计""可对账/不可对账""整车"）不属于状态标签，保持原有样式，不要强行套状态组件。
  `来源：2026-11-10 会话 d70cb29e（状态标签统一）；源码：frontend/src/components/ReconStatusTag.vue`

# 二、页面设计

## 2.1 框架布局尺寸（硬性）

| 项 | 值 |
|---|---|
| 顶栏 header | **56px** |
| Logo 区 | **60px** |
| 标签栏 | **32px**，嵌在顶栏内、与右侧快速搜索同一行 |
| 侧边栏 | **208px**，折叠后 **56px** |
| 页面内边距 | 左右/上下 **16px** |
| 表格行高 | **42px** |
| 核心内容区 | 必须最大化屏占比，首页不得有冗余按钮与重复标签页入口 |

- 高度链路：`.main`（`flex:1; min-height:0`）→ `.page-container`（`height:100%; display:flex; flex-direction:column`）→ `.page-content`（`flex:1; min-height:0; display:flex; flex-direction:column`）。
- 布局高度链前提：`.main` 必须 `flex:1; min-height:0`；新增标签栏后仍成立。
  `来源：2026-10-28 会话 6ae14f4f（设计令牌统一）；源码：variables.css 255-260、common.css；project_memory 模板 K/L`

## 2.2 菜单与导航（硬性 + 基线）

- 菜单为两级结构：一级业务模块，二级具体页面；一级菜单排序值决定导航顺序，同级内按 `sort` 升序。
- luohuo 的导航顺序（业务示例，yunshu 需替换为自身模块）：
  1. 首页/看板（affix，不可关闭）
  2. 落货管理
  3. 到货管理
  4. 提货管理
  5. 派送管理
  6. 外转管理
  7. 财务/核销
  8. 系统管理
  `来源：project_memory 5.4~5.9 菜单 id 与路径`
- 菜单图标必填（见 1.6）。
- 业务单据编号一律渲染为可点击链接进入详情页：运单号 → `/biz/waybill/detail?id=xxx`，车次号 → `/unload/trip/view`；全局统一，无例外。
  `来源：2026-10-27 会话 6adf0e8e（全局约定）、2026-11-09 会话 d70cb29e（统一路由）`

## 2.3 多标签页（基线）

- 状态存 Pinia `stores/tags.js`，结构 `{ key, path, fullPath, title, affix }`；**key 必须用 `route.fullPath`**，同一路由不同参数才能并列为独立标签。
- 标签栏嵌在顶栏 header 内、与右侧快速搜索同一行（`flex:1; min-width:0`，垂直居中），不单独占一行。
- `/dashboard` 为 affix 首页，不可关闭；关闭当前标签后优先跳右侧，其次左侧，兜底首页。
- 缓存：`<keep-alive :max="15">`，`:key="currentRoute.fullPath"`；持久化 `sessionStorage('app_tags_view')`。
- 去重三重防线：路径归一化、语义主键匹配（去 query/hash）、持久化前扫尾；禁止只按 fullPath 精确匹配。
- 标签标题：`addView` 对已存在标签不改标题；页面要改标签名必须用 `updateTitle(key, title)`。
- 使用 SmartTable 的页面，`onActivated` 必须重新 `bindObservers()` + `scheduleMeasure()`。
  `来源：2026-10-28 会话 6ae14f4f（标签栏三重去重）；project_memory 模板 L`

## 2.4 页面结构（硬性）

### 2.4.1 列表页

固定三段式，自上而下：

1. **工具条**：左侧业务按钮组；右侧固定工具组，顺序为 `重置筛选 → 导出 → 列设置 → 分页`。
2. **表格**：撑满剩余高度，自带合计行（表格内 footer）。
3. **页脚**（可选）：勾选统计等。

- 工具条左右之间必须有 1px 竖分隔线（`--color-border-light`），无业务按钮时分隔线自动隐藏。
- 右侧工具组 `flex:0 0 auto`，永不换行、不打散；窄屏只允许左侧业务组收缩。
- 工具组视觉顺序用 CSS `order` 固定，DOM 顺序可以不同。

# 三、表格 / 列表设计

## 3.1 标准列表页（硬性）

每个列表页必须具备以下 **五项核心能力 + 统一分页**，且由同一份列声明单点驱动：

1. 表头筛选（除序号、操作外每列都有）
2. 列设置（显隐 + 列序，可保存、刷新保持、可恢复默认）
3. 字段排序（除序号、操作外每列可排序）
4. 合计行
5. 导出（按当前可见列 + 当前筛选 + 当前排序）
6. 分页（含条数统计，统一组件）

> 口径说明：project_memory 把前 5 项称为"五项能力"；2026-11-09 家伟的验收六项为"逻辑验证 / 字段筛选框 / 列设置 / 字段排序 / 导出 / 合计行"，分页不在验收六项内但为页面必备。本文不混用这两个"六"。

- 新增列表只接一个入口（`useListTable` / `ListPage`），新增字段只加一项声明即自动继承五项能力；禁止在页面分散手写筛选控件、排序开关、合计取值、导出列与表头文案。
- 例外场景（内嵌子表、按勾选汇总、树形表）必须先报家伟确认后单独处理。
  - **树形配置表（菜单管理）例外**（2026-11-20 家伟确认）：菜单管理是树形配置表，**不做分页、不做合计行、不做导出**，只保留“筛选 + 刷新”；列设置与字段排序同样不提供。其余列表页不得援引此例外。
- 页面内嵌子表同样必须配导出与独立列设置（独立 `pageKey`，互不影响、可分别恢复默认）。
- 验收动作：新增一个字段并说明它在五项能力中的表现。
  `来源：2026-11-09 家伟要求（project_memory 1.1、模板）；源码：useListTable.js / ListPage.vue`

## 3.2 列宽（硬性）

### 3.2.1 基本规则

- 表头字段名称**禁止换行**（全局 `white-space: nowrap`）。
- 列宽根据字段名与内容自动计算并设置最小列宽，禁止手动硬编码固定宽度。
- **全局最小列宽 80px**，由 `SmartTable` 的拖拽下限实现（`MIN_COLUMN_WIDTH = 80`），不是 `colgroup` CSS。
  > 历史写法：project_memory 3.2 曾写"由 `colgroup col { min-width:80px }` 实现"，该写法已于 2026-10-29 删除（会导致窄列渲染超宽、横向滚动异常）。现按源码：最小宽由 SmartTable 拖拽下限保证。
- 列宽自适应：宽度 = `max(表头所需宽, 该页数据最宽值 + 内边距)`，不低于列自身 `minWidth`；超过上限时改为固定宽度 + 省略号 + hover tooltip。
- 自适应最大宽度默认 **240px**，页面可用 `:auto-width-max` 覆盖。
- 用户手动拖过宽度的列，脱离自适应，避免翻页时被回写覆盖（宽度抖动）。
  `来源：2026-10-27 会话 6ae0456b（表头不换行 + colWidth）；2026-11-10 会话 d70cb29e（列宽自适应由基座负责）；源码：SmartTable.vue、colWidth.js`

### 3.2.1.1 yunshu 覆盖（2026-11-20 家伟定稿，优先级高于本节其余内容）

> 以下为标准列表配置，落在 `frontend/src/components/base/SmartTable.vue`，机构管理与菜单管理共用。与 luohuo 冲突时以本小节为准，禁止照抄 luohuo 旧实现。

1. **列宽允许手动拖动**。可拖的前提是 `SmartTable` 必须给 `el-table` 传 `border`——Element Plus 源码 `handleMouseMove` 首行是 `if (!props.border ...) return`，没有 border 时拖拽手势根本不会启动；同时必须绑定 `@header-dragend` 才能记录用户宽度。yunshu 基座默认开启这两项。
2. **拖拽下限 80px**；拖拽结果夹在 `[80, 320]`，不因原 `minWidth` 更大而回弹。
3. **未拖动过的列自适应**：宽度 = `max(表头所需宽, 当前页最宽内容 + 内边距)`，不低于列 `minWidth`。
4. **最大列宽统一 320px，不按列类型区分**（luohuo 的 240px 在 yunshu 作废）。自适应与手动拖拽都受上限约束；超过上限固定为该宽度，走省略号 + 表格级 tooltip，避免超长列吃掉整行。
5. **用户拖过的列以用户宽度为准**，持久化到 `localStorage`（`persistKey` → `yunshu:table-widths:<key>`），自适应不再覆盖；列设置「恢复默认」时清空用户宽度并恢复自适应。
6. **自适应重算时机**：数据变化（分页/筛选）、列显隐变化、容器尺寸变化（含侧栏折叠）、窗口缩放、字体加载完成。
7. 表格统一开启 `border` 与 `show-overflow-tooltip`；列设置显隐、导出、筛选与列宽互不干扰。
8. **每列默认可排序，操作列除外，且必须走服务端排序**（luohuo 默认不排序，此处为 yunshu 覆盖）：
   - 基座 `SmartTable` 对带 `prop` 的列自动补 `sortable="custom"`，操作列（无 `prop`）天然不参与；页面可用 `:sortable="false"` 显式关闭。
   - 点击表头升序/降序/取消，通过 `sort-change` 把 `sortBy`（列 `prop`）+ `sortOrder`（`asc`/`desc`）传给后端，禁止前端只排当前页。
   - 日期、状态、是否末端、类型等非文本列按语义排序（时间/布尔/枚举值），不得按字符串排序。
   - 树形表格（菜单管理）排序只作用于同级兄弟节点，保持层级与缩进不变；平铺列表（机构管理）直接按字段全局排序。
   - 关联解析列（如创建人/最后修改人）排序按解析后的姓名比较，不按关联 id；关联数据缺失时排最后。
9. **权限与数据边界（yunshu 硬性，覆盖 luohuo）**：
   - **角色与数据权限彻底解耦**：角色只控制菜单与按钮可见性，不含任何数据范围语义；数据范围挂 `sys_user.data_scope`，配置入口在用户管理，不在角色管理。
   - **平台配置类接口不受数据权限影响**：角色管理、菜单管理、用户管理、机构管理本身、登录与 `/auth/info` 永不按数据范围过滤；数据权限只作用于业务数据表。
   - 前端不得在角色页面出现“数据权限/数据范围”列、筛选项或配置项；角色抽屉只保留名称、编码、描述、状态、备注。
   - 用户抽屉的“数据权限”Tab 提供四项：全部 / 本机构 / 本机构及以下 / 仅本人，默认“本机构及以下”；“自定义机构”预留但不展示。
   - 过滤是否真正生效由后端开关 `yunshu.data-scope.enabled` 控制，默认关闭；**开启过滤属于单独评审项**，不得随用户管理上线顺带打开。

## 3.3 表头与筛选（硬性）

- 表头字段名**水平居中**；表体对齐由列 `align` 决定。
- 含筛选控件的表头：上面一行列名（12px/600，居中），下面一行筛选控件；表头左右 padding **6px** 对称且尽量小，控件 `width:100%` 填满内容区。
- 有筛选的表头 `min-height: 52px`，上下 padding 6px。
- 筛选控件内文字、占位符、选中值一律居中（输入框、区间输入、el-select 占位）。
- 居中的实现要点（最容易踩坑）：
  - `.el-input__suffix` 必须 `position:absolute; right:4px`，否则清除图标占 22~36px 把 input 挤窄，文字相对外框偏左；
  - `.el-select__suffix` 必须 `position:absolute; right:6px`，否则"全部"等文字偏左约 18px；
  - `.el-select__placeholder` 是独立绝对定位元素，必须单独 `text-align:center`；
  - 排序箭头 `.caret-wrapper` 绝对定位 `right:8px`、宽 12px，可排列 `padding-right:20px`。
- 验收方法：canvas `measureText` 量文字宽度，比较文字到外框左右边缘距离，差 ≤2px 才算居中；只看 `text-align` 计算值会误判。
- 除「序号」「操作」列外每列必须有筛选控件，含派生/关联列（由后端提供代理参数）。唯一例外：只读日志表。
- 运单号等单号列一律用多模式匹配（等于/不等于/模糊/左/右/批量），输入即自动弹出方式下拉；默认 `like`。
- 列筛选配置：普通文本字段可选单模式/多模式，运单号、关联单号、车次号默认多模式，其余默认单模式；下拉字段可选单选/多选，**默认多选**。
  `来源：2026-10-27 会话 6ae0456b、2026-10-28 会话 6ae14f4f（多模式/多选默认）、2026-10-27 会话 6adf0e8e（单号六种匹配）；源码：common.css 646-773、tableFilter.js、WaybillNoFilter.vue`

## 3.4 列顺序（硬性）

- 结构列顺序固定：**勾选列 → 序号列 → 数据列 → 操作列**。
  - 需要多选时，勾选列必须是表格第一列，排在序号之前；禁止放在金额列、状态列或操作列之后。
  - Element Plus 中 `fixed="left"` 会渲染到最左；若页面还有其他 `fixed="left"` 列，勾选列会被挤到第二列——要保证第一列就不要给它 `fixed`，或确保没有更左的固定列。
- 状态字段紧跟业务主键：运单状态跟在运单号后，车次状态跟在车次号后（全局统一）。
- 操作列固定在最右（`fixed="right"`），宽度默认 160px，居中。
- 默认显示列调整必须放在合理业务位置；列序以设计方案为准，方案没有的列不得自行添加。
- 默认显示列只保留业务主链路必需字段，次要字段默认隐藏，由列设置开启；默认隐藏的数值列被用户打开后，合计行会自动纳入（SmartTable 按可见列渲染合计）。
  `来源：2026-10-27 会话 6adf0e8e（导入页 18 显示 / 22 隐藏）、2026-11-04 会话 196d68a4（隐藏列合计跟随）`
- **「最后修改人」「最后修改时间」**：标准业务列表（运单、提货、派送、外转、系统管理）默认展示；对账/账单类宽表按设计稿可不展示（源码现状：客户对账、承运商对账页面未展示）。历史值"所有列表一律必备"已调整为按页面类型区分。
  `来源：2026-10-24 会话 6adc71a0；2026-10-29 会话 6ae2b140（状态紧跟单号）；2026-11-09 会话 d70cb29e（勾选列第一列）；源码：ListPage.vue`

## 3.5 排序（硬性）

- 除「序号」「操作」外所有列必须支持排序，含筛选列、金额列、日期列、关联/派生列。
- 前端：列声明加 `sortable:'custom'`；排序变化统一写 `queryForm.sort_by / sort_order`；点击表头后 `page` 重置为 1 并立即重查。
- 「重置筛选」必须同时清空 `sort_by/sort_order` 并调用表格 `clearSort()`（SmartTable 必须转发 `expose` 的 `clearSort`）。
- 后端统一接收 `sort_by + sort_order`，字段名白名单校验；白名单外忽略并 `warning`，不返回 400；命中时排序键后追加 `id DESC` 作为次序键。
- 翻页、筛选、导出都要带当前排序；导出文件行序与列表一致。
- 以下三类必须显式 `sortable:false` 并注明：① 明细聚合值；② 多对多或"取最新一条"派生；③ 纯前端文案/计算列。禁止"点了没反应"。
- 未指定排序时沿用各页既有默认（通常 `create_time desc`），不得因加排序改变默认行为。
- 排序箭头样式：绝对定位贴右边缘（`right:8px`、宽 12px，即箭头左沿距列右边界约 20px），可排列 `padding-right:20px`；验收口径按记忆为"距列右边缘 21px"（含 1px 余量），与输入框/下拉框重叠面积为 0。
  `来源：2026-11-03 家伟要求（project_memory 3.4）；源码：common.css 665-700`

## 3.6 合计行（硬性）

- 每个列表页必须在列表下方显示合计行，统计所有数值型业务列；无数据时隐藏（不显示"合计 0"）。
- 统计口径 = **当前筛选条件下的全部数据**，不是当前页：后端复用列表同一查询（同筛选、同数据权限），去掉分页与排序后 `SUM`；禁止在 Python 里对当前页求和。
- 响应契约：`summary` 与 `data`/`total` 同级；每页维护显式合计字段清单，不允许自动猜"数字列"。
- 计入范围：金额、数量、件数、重量、体积、`sum_*` 聚合列；排除 ID/单号/日期时间/状态码/比率/纯文本派生列。
- 视觉：
  - 首列（序号列）显示 `合计（共 N 条）`，N 为接口 total；
  - 数值列右对齐、千分位、金额两位小数；不参与合计的列显示 `--`；
  - 合计行加粗、底色略深一档；`position:sticky; bottom:0`，横向滚动跟随列；
  - 不遮挡最后一行、不额外产生纵向滚动。
- 翻页合计不变；筛选/排序变化后合计随同一次请求更新，不得二次请求。
- 合计行单元格必须保持 `overflow:visible`，否则首列"合计（共 N 条）"会被省略成"18…"。
- 合计行颜色用 `summaryFields + tone` 声明，禁止按表头文字定位列序号。
  `来源：2026-11-04 家伟要求（project_memory 3.5）；2026-11-10 会话 d70cb29e（tone 声明）；源码：SmartTable.vue、common.css 801-811`

## 3.7 分页（基线）

- 分页位于工具条右侧、列设置之后（新标准），不再放表格底部。
- 默认每页 **20** 条，可选 **20 / 50 / 100**。
- 分页器 `size="small"`、`background`；页码按钮 30×30px、圆角 6px、间距 3px，激活态主色底白字。
- 宽度自适应降级顺序：
  1. `total + sizes + 页码7 + jumper`（≥600px）
  2. `total + sizes + 页码5 + jumper`（≥480px）
  3. `total + sizes + 页码5`（≥380px）
  4. `total + sizes + 上/下页`（≥200px）
  5. `total + 上/下页`（<200px）
- 分页器 `flex:none`，永不换行。
  `来源：2026-11-11 会话 4f46c1d9（工具栏顺序）；源码：TablePager.vue、common.css 1060-1094`

## 3.8 勾选列（硬性）

- 位置：表格第一列，排在序号之前。
- 对齐：勾选框在单元格内**水平与垂直均居中**，表头勾选框同步居中；走全局样式统一实现，禁止逐页手写。
- 宽度：原生多选 50px，自定义勾选 44px。
- 实现要点：
  - 原生 selection 列 `.cell` 默认是 inline-flex 且带 padding，`justify-content:center` 不生效，必须改为块级 flex 并撑满单元格；
  - `.el-checkbox` 默认有 `margin:0 5px 12px`，必须清零，否则垂直偏 6px；
  - 表格级 `show-overflow-tooltip` 会给单元格加 `.el-tooltip{min-width:50px}`，把自定义勾选列撑宽偏移 → 必须对勾选/单选列 `min-width:0`；
  - 抽屉、弹窗、展开行子表共用同一套 el-table 结构，全局选择器自动覆盖。
- 验收：勾选框中心与单元格中心偏差 ≤0.5px（1680 / 1366 两档）。
  `来源：2026-11-09 会话 d19c18b4、2026-11-10 会话 d19c18b4（全局居中与 min-width 修复）；源码：common.css 820-868`

## 3.9 空态（基线）

- 统一 `el-empty`：`image-size="80"`，文案 **"暂无数据"**。
- 空态在表格内容区垂直居中，不得因表头高度变化出现 10px 级跳动（已知历史差异，属可接受范围）。
  `源码：ListPage.vue；2026-11-09 会话 d19c18b4（空态 10px 差异保留）`

## 3.10 操作列与链接（基线）

- 操作列固定右侧、居中；按钮用 `is-link` 紧凑样式，字号 13px。
- 无权限按钮用 `v-hasPerm` 控制；不可操作的按钮置灰并给出原因提示，禁止直接隐藏导致"功能消失"的误解（业务按钮按设计稿执行）。
- 业务单据号一律可点击跳详情（见 2.2）。
- 单元格内 `el-link` 必须左对齐，超宽只在右侧省略，避免首尾同时被裁。
  `源码：common.css 813-818；project_memory 3.3`

## 3.11 单元格复制与溢出（基线）

- 所有列表字段值右侧自带快速复制按钮，由全局 `setupTableCellCopy()` 注入，页面不要自己写。
- 按钮 16×16px、绝对定位 `right:3px`、垂直居中；单元格 hover 时淡入；复制成功提示"已复制"；`navigator.clipboard` 失败回退 `execCommand`。
- 排除：操作列、含表单控件单元格、空值单元格。
- 单元格：`position:relative; padding-right:22px; white-space:nowrap; overflow:hidden; text-overflow:ellipsis`。
  - `overflow:hidden` 必须保留：纯文本节点不是元素，父级若 visible，nowrap 文本会画到相邻列造成重叠。
  - 复制按钮位于 padding 区内，不会被裁。
- 表体所有单元格默认 `show-overflow-tooltip`（SmartTable 默认开启）。
  `来源：2026-10-28 会话 6ae14f4f（复制按钮被裁剪修复）、2026-11-07 会话 d19c18b4（列内容重叠修复）；源码：common.css 775-899`

## 3.12 上下列表（车次管理等）（硬性）

- 容器 `.page-content--split`，两个面板 `.split-panel` 设 `flex:1 1 0; min-height:0`，精确平分剩余高度。
- 两表都必须有分页 + 条数统计；下列表全量拉取后前端分页；切换主表选中时下列表重置到第 1 页。
- 跨页勾选不丢：`row-key` + `reserve-selection`。
- 表格内部的"汇总 + 分页"区域必须移到 `.split` 之外作为页面级页脚，否则会占用约 38px 导致两表无法等高。
- 实测：1680 下两表容器各 368px，1366 下各 246px；页面无整页滚动，各表表内滚动、表头固定、合计行常驻。
  `来源：2026-11-10 会话 d70cb29e（上下两表等高）；project_memory 模板 K`

## 3.13 列表撑满与滚动（硬性）

- 所有列表页表格宽度 100% 填满内容区、高度自适应到可视区底部，**既不留空白也不出现整页滚动条**。
- 表格高度由 SmartTable 自动测算：仅当父容器命中 `.page-content / .split-panel / .table-fill / .table-wrap / .transfer-panel / .el-tab-pane` 时启用；可用高度 = 容器高 − 兄弟元素高 − row-gap，下限 **200px**。
- 页面不要给列表表格传 `height` / `max-height`（传了即关闭自适应）；弹窗内小表格除外。
- 验收：1440×900、1280×720（及 1366×768、1680×950）两档以上实测，无整页滚动、无半屏、上下双列表平分。
  `来源：2026-10-30 家伟强调（project_memory 模板 K）；源码：SmartTable.vue`

## 3.14 导出（硬性）

- 所有列表页必须带导出，统一 `ExportButton.vue` + 后端 `POST /api/v1/export/{module}`。
- 导出列 = 当前可见列（自动补序号列）；数据 = 当前筛选条件（含数据权限）+ 当前排序；xlsx。
- 「导出当前页」「导出全部」两档；全部导出按 2000 条/批、上限 10 万行。
- 子表各有一套导出与列设置，跟随各自表的可见列/筛选/排序。
- 枚举列必须补中文格式化器，导出不得出现英文枚举值。
  `来源：2026-10-27 会话 6adf0e8e（导出统一规范）；project_memory 3.1`

# 四、硬性流程要求（与前端交付直接相关）

1. **设计评审前置**：新模块/新页面先输出设计方案与前端原型，与家伟确认字段后才进入开发；单模块逐个开发，每完成一个模块经确认后再做下一个。
   `来源：2026-10-26 / 2026-10-30 会话（家伟明确模块开发流程）`
2. **原型为视觉唯一基准**：像素级落地；开发前逐区块提取原型样式参数；实现后浏览器截图与原型对比验收。
3. **字段与模型核对**：原型中每个字段逐一核对后端模型——完全匹配直接用；近似需后端聚合；模型不存在必须先问家伟（加字段还是占位"-"）；模型有但原型未画则不增不减。
4. **禁止自行发挥**：未要求的字段、列、提示文案、提示条、区块、面板、按钮一律不得添加。
5. **冲突必须先问**：与既有规范冲突时指出冲突、给选项、等裁决。
6. **交付验收六项**（列表页/子表类）：逻辑验证、字段筛选框、列设置、字段排序、导出、合计行；缺一视为未完成。
7. **布局测试与功能测试同等重要**：必须附布局读数（列位置、元素顺序、两个视口截图），禁止只测数据正确性。
8. **规范符合性自检表**：逐列列出"列名 × 是否有筛选控件 × 控件类型 × 是否通到后端"；`buildFilter().__stats()` 的 `missing` 必须为空并贴报告；视觉规范必须截图或逐列实测。
9. **完成即反查**：构建通过、接口实测、浏览器实测，缺一不可。

`来源：project_memory 一、协作流程（2026-10-28 / 2026-10-30 / 2026-11-07 / 2026-11-09 家伟要求）`
